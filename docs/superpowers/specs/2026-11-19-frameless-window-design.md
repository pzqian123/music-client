# 无边框桌面窗口设计

日期：2026-11-19  
状态：已确认，待实现

## 目标

将 Windows 版改为无原生标题栏的桌面窗口，在应用内部提供品牌标题区、
窗口拖动区和最小化、最大化/还原、关闭按钮，同时保持缩放、系统吸附、
多显示器和 DPI 行为正常。

Android 和其他非 Windows 平台保持现有窗口与导航行为。

## 非目标

- 不改变搜索、播放、官方网页和沉浸歌词的业务逻辑。
- 不实现自定义的 Windows Snap Layout 弹出菜单。
- 不重新设计页面内容布局。
- 不在移动端显示桌面窗口控制按钮。

## 视觉

- 窗口无原生标题栏，Flutter 内容延伸到整个窗口。
- 应用顶部增加固定 44px 高的自定义标题区。
- 标题区左侧显示应用图标与“音乐聚合”，右侧显示三枚圆形窗口按钮。
- 普通页面标题区使用深色半透明背景和 1px 底部分隔线。
- 沉浸模式标题区使用更透明的背景，但不覆盖歌词内容。
- 窗口小于 520px 宽时隐藏标题文字，仅保留图标和窗口按钮。

### 窗口按钮

- 顺序：最小化、最大化/还原、关闭。
- 按钮视觉直径 32px，点击区域至少 40px。
- 默认使用低对比度图标；悬停动画约 140ms。
- 最小化悬停为浅灰色。
- 最大化/还原悬停为柔和绿色。
- 关闭悬停为柔和红色。
- 最大化状态下图标切换为“还原”。
- 每枚按钮提供 Tooltip、键盘焦点和语义标签。

## 交互

- 标题区除去按钮和控制区域外均为拖动区。
- 按下拖动区并移动时调用窗口拖动，不依赖系统标题栏。
- 双击拖动区切换最大化与还原。
- 单击最大化按钮同样切换最大化与还原。
- 点击按钮、输入控件和页面交互区域不会触发行窗口拖动。
- 官方网页显示时，窗口按钮仍保持可用。
- 窗口支持四边和四角缩放、Windows 吸附、最小化、关闭与多显示器移动。
- `Alt+F4` 继续由 Windows 系统处理。

## 架构

### `DesktopWindowService`

定义界面所需的平台能力：

```dart
abstract interface class DesktopWindowService {
  Future<void> minimize();
  Future<void> toggleMaximize();
  Future<void> close();
  Future<void> startDragging();
  Future<bool> isMaximized();
}
```

Windows 实现基于 `window_manager`。测试使用记录调用的假实现；Android
和非 Windows 平台使用不渲染标题按钮的运行路径。

### 启动配置

Windows 在 `runApp` 前完成：

- 隐藏原生标题栏和系统窗口按钮。
- 设置 `1280 × 720` 初始尺寸和合理的最小尺寸。
- 等待窗口初始化完成后显示并聚焦，避免原生标题栏闪烁。
- 初始化失败时继续使用系统原生标题栏，保证窗口始终可关闭。

### `AppWindowChrome`

- 通过 `MaterialApp.builder` 包裹所有应用页面。
- 包含 44px 标题区和下方实际页面内容。
- 页面内容位于标题区下方，不以覆盖层遮住业务页面。
- 搜索、播放、连接、官方网页和沉浸歌词共享同一窗口控件。
- 非 Windows 平台直接返回子页面。

### `WindowTitleBar`

- 显示应用标识和窗口按钮。
- 将空白区域包装为拖动区。
- 根据假服务或真实服务返回的最大化状态更新按钮图标。
- 按钮区域独立于拖动区，避免点击误触发窗口移动。

## 状态流

1. 启动服务隐藏原生窗口边框。
2. `AppWindowChrome` 查询当前最大化状态。
3. 用户拖动空白区时调用平台拖动。
4. 用户双击或点击最大化按钮时切换窗口状态。
5. 服务返回新状态后更新最大化/还原图标。
6. 关闭按钮调用平台关闭，允许应用按现有流程释放资源。

窗口状态属于平台层，不写入 `MusicController`，避免业务状态与桌面窗口耦合。

## 降级与错误处理

- 平台服务初始化失败：保留系统标题栏，不显示会误导用户的无效按钮。
- 单次窗口操作失败：界面不崩溃，记录错误并保持原窗口状态。
- Windows 外的平台：不创建窗口控制按钮。
- 按钮操作期间避免重复提交最大化请求。
- 退出应用仍走正常窗口关闭和 Flutter dispose 流程。

## 测试策略

### Widget 测试

- 三枚按钮分别调用最小化、最大化切换和关闭。
- 最大化状态变化后按钮图标切换。
- 按钮点击不会调用拖动。
- 标题空白区域可触发拖动。
- 520px 以下隐藏标题文字但保留按钮。
- 720p、1080p 和窄窗口均无溢出。
- 非 Windows 测试运行不显示窗口控制按钮。

### 平台验证

- Windows 实机确认无原生标题栏闪烁。
- 鼠标拖动窗口位置正常。
- 双击切换最大化/还原正常。
- 最大化、最小化和关闭按钮正常。
- 四边和四角缩放正常。
- Windows 吸附和多显示器移动正常。
- 官方网页和沉浸歌词下按钮均可操作。

## 验收标准

- 启动后仅存在应用内标题栏，不出现双标题栏。
- 应用内三个窗口按钮行为与系统窗口按钮一致。
- 窗口仍可缩放、吸附和跨显示器移动。
- 标题栏不遮挡页面内容，沉浸歌词焦点位置保持稳定。
- Android 构建和现有界面不受影响。
- `flutter analyze` 无问题，完整测试与 Windows 构建通过。
- 保存一张 Windows 无边框窗口实机截图作为验证证据。
