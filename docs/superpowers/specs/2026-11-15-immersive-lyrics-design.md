# 沉浸式 Apple Music 风格歌词设计

日期：2026-11-15  
状态：已确认，待实现

## 目标

重构 Windows 与 Android 的沉浸歌词模式，使当前行成为持续变化的视觉焦点，
同时保持长时间观看安静、克制，不模仿厂商品牌素材。

首版采用居中式 Apple Music 构图，不加入对唱分栏、翻译或声部模型。

## 非目标

- 不复制 Lyricify 的闭源代码、字体、图标、截图或其他受保护素材。
- 不引入演唱会粒子、3D 封面、频谱或大型舞台效果。
- 不改变搜索、队列、播放、来源切换和歌词解析契约。
- 不把歌词动画逻辑继续堆入 `immersive_lyrics_page.dart`。

## 视觉方向

### 背景

- 使用当前专辑封面的低透明度模糊副本作为底层。
- 叠加两组由专辑主色推导的缓慢流动径向渐变。
- 没有封面时只显示主色氛围背景。
- 背景在切歌时交叉淡化，不随播放时间高频重建。
- 不使用高饱和霓虹色，文字区域保持足够对比度。

### 歌词焦点

- 歌词焦点位于画面中心略偏上。
- 常规窗口显示约 7 行；高度受限时减少到约 5 行。
- 当前行字体最大、亮度最高；相邻行逐级缩小、变淡。
- 当前行在焦点区保持视觉居中，切行使用弹簧惯性而非直接跳转。
- 切行时当前行向右上轻微浮出，前后行产生有限的挤压和拖拽感。
- 动画收敛时间约 420ms，不产生连续晃动。

### 逐字与间奏

- 只有可靠逐字时间戳才启用逐字扫光和弱发光。
- 逐字不足时回退为整行同步。
- 相邻歌词行之间纯音乐空档超过约 4 秒时，显示三个轻微呼吸的圆点。
- 只有静态歌词时不显示呼吸点；无歌词时保留明确空状态。

### 顶部与底部控件

- 顶部保留返回按钮、歌曲名和艺人，弱化专辑、来源与时间信息。
- 底部使用半透明玻璃控制条，包含细进度线、上一首、播放/暂停和下一首。
- 鼠标静止 3 秒后，顶部与底部控件降低透明度；移动鼠标或使用键盘后恢复。
- 控件淡出不能改变布局，也不能遮挡歌词点击。

## 交互

- 点击任意歌词行，跳转到该行开始时间。
- `Esc` 退出沉浸模式。
- `空格` 播放/暂停。
- 左右方向键前后跳转 5 秒。
- Android 返回键继续退出沉浸模式。
- 窗口缩放时自动调整可见行数，当前行保持焦点。
- 切歌后背景、标题和歌词短暂交叉淡化，不中断音频。

## 架构

### `ImmersiveLyricsPage`

页面只负责：

- 连接 `MusicController` 的播放、歌词和视图状态。
- 组合背景、焦点歌词和控件。
- 处理键盘、返回键和沉浸模式退出。
- 组合歌词行点击后的 `seekTo` 行为。

### `ImmersiveAmbientBackdrop`

- 输入：专辑主色、可选封面字节、当前歌曲稳定键。
- 输出：模糊封面、流动主色渐变和切歌淡入。
- 以歌曲/封面为缓存边界，不监听播放位置。

### `FocusLyricsViewport`

- 输入：`LyricTimeline`、当前位置、沉浸布局参数。
- 根据当前行索引计算前后行的目标位置、缩放、透明度和模糊层级。
- 使用弹簧模拟驱动焦点偏移，仅在当前行变化时启动。
- 负责空档检测并显示呼吸点。
- 处理歌词行点击的范围和跳转回调。

### `FocusLyricLine`

- 输入：单行歌词、是否为焦点行、逐字进度、是否启用动画。
- 逐行模式只执行整行亮度和位移动画。
- 逐字模式只重绘当前行的文字着色和弱发光。
- 静态歌词不使用逐字动画。

### `ImmersiveControls`

- 输入：播放状态、进度、前后曲可用性和鼠标活跃状态。
- 负责玻璃控制条、进度、快捷键提示和控件淡出。
- 不直接依赖服务商或网页播放器。

## 数据流

1. `MusicController.playback.position` 继续作为唯一播放时间源。
2. `LyricTimeline.activeLineAt` 计算焦点行。
3. 焦点行发生变化时，视口启动一次切行弹簧动画。
4. 焦点行内的 `wordProgressesAt` 只驱动当前行文字重绘。
5. 用户点击歌词时，将目标时间传给现有 `MusicController.seekTo`。
6. 切歌时使用新的稳定曲目键重建背景与歌词状态。

不新增第二套播放时钟，不在组件内推导播放状态。

## 性能约束

- 使用 `RepaintBoundary` 隔离背景、歌词和底部控件。
- 背景只在歌曲或封面变化时重建。
- 非焦点行不计算逐字进度。
- 避免对整个屏幕持续使用 `BackdropFilter`；模糊封面在背景层完成。
- 窗口不可见或暂停时不启动无意义的切行动画。
- 目标是在当前开发机上维持流畅的 60 FPS。

## 无障碍与降级

- 当系统启用减少动态效果时：
  - 关闭弹簧位移、上浮、背景漂移和呼吸动画。
  - 保留 120ms 以内的透明度和亮度切换。
  - 歌词与播放时间同步行为不变。
- 键盘焦点和快捷键保持可用。
- 歌词文字使用可读的系统字体与足够对比度。
- 无封面、无逐字、静态歌词与无歌词都使用明确降级。
- 动画异常不得影响播放、切歌或退出沉浸模式。

## 测试策略

### Widget 测试

- 焦点行随播放位置变化。
- 点击歌词行调用正确的跳转时间。
- 逐字进度只作用于当前行。
- 长间奏显示呼吸点，短间奏不显示。
- `Esc`、空格和左右方向键行为正确。
- 减少动态效果时禁用大幅位移。
- 720p、宽屏和窄窗口无布局溢出。
- 无歌词、静态歌词与逐字歌词均稳定渲染。

### 回归测试

- 进入和退出沉浸模式不改变播放位置。
- 沉浸模式下切歌仍更新标题和歌词。
- 现有搜索、队列和播放控制测试保持通过。

### 视觉验证

- 使用 Windows 调试版截图验证普通歌词、逐字歌词和长间奏三种状态。
- 对比切行前后截图，确认焦点行位移连续且没有溢出。

## 验收标准

- 居中式构图在 720p、1080p 和窄窗口中保持当前行焦点。
- 切行使用连续弹簧位移，不出现普通列表式跳滚动。
- 逐字高亮与真实播放时间一致，发光不过度。
- 背景使用当前专辑视觉信息，但不会干扰歌词阅读。
- 鼠标静止后控件淡出，移动后恢复。
- 减少动态效果模式仍可完整使用。
- 现有 147 个测试及新增测试全部通过。
- `flutter analyze` 无问题，Windows 实际构建成功。
